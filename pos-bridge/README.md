# سرویس پل کارت‌خوان (PosBridge)

مرورگر نمی‌تواند مستقیماً `pec.pcpos.dll` (کتابخانهٔ PC-POS پارسیان) را صدا بزند.
این سرویس کوچک ویندوزی روی همان کیوسک اجرا می‌شود، فقط روی `127.0.0.1` گوش می‌دهد
و درخواست پرداخت وب‌اپ را به دستگاه پوز می‌فرستد.

```text
کیوسک (وب‌اپ)  --HTTP-->  PosBridge (127.0.0.1:9099)  --DLL-->  دستگاه پوز
```

## پیش‌نیاز

- ویندوز ۱۰/۱۱
- .NET SDK 8 (برای build؛ خروجی روی .NET Framework 4.8 اجرا می‌شود)
- درایور دستگاه پوز نصب و پورت COM شناخته‌شده
- فایل `pec.pcpos.dll` (از بستهٔ پارسیان)

## نصب

1. فایل DLL را در مسیر `pos-bridge/lib/pec.pcpos.dll` قرار دهید.
2. در همین پوشه اجرا کنید:

```bat
dotnet build -c Release
```

3. `appsettings.json` را تنظیم کنید:

| کلید | توضیح |
| --- | --- |
| `listenUrl` | آدرس محلی سرویس (پیش‌فرض `http://127.0.0.1:9099/`) |
| `terminalId` | شمارهٔ ترمینال — مقدار فعلی: `5634056` |
| `signCode` | کد امضای دریافتی از بانک (در صورت نیاز) |
| `comPort` | پورت اتصال دستگاه، مثلاً `COM3` |
| `timeoutSeconds` | حداکثر زمان انتظار برای کشیدن کارت |
| `simulate` | `true` برای تست بدون دستگاه واقعی |

4. `run.bat` را اجرا کنید (یا در Task Scheduler برای اجرای خودکار در ورود به ویندوز ثبت کنید).

## سرویس‌ها

| متد | مسیر | توضیح |
| --- | --- | --- |
| GET | `/health` | بررسی سلامت؛ خروجی `{ status, terminalId, simulate }` |
| POST | `/pay` | بدنه: `{ amountRial, invoiceNumber, terminalId }` |
| POST | `/cancel` | لغو تراکنش جاری |

پاسخ `/pay`:

```json
{
  "success": true,
  "responseCode": "00",
  "message": "تراکنش موفق",
  "refNumber": "123456789012",
  "maskedPan": "6221-****-****-1234",
  "terminalId": "5634056"
}
```

## تست بدون دستگاه

`"simulate": true` را در `appsettings.json` بگذارید؛ سرویس بعد از چند ثانیه پاسخ موفق
آزمایشی برمی‌گرداند تا کل جریان سبد خرید → پرداخت → رسید قابل تست باشد.

## نکات فنی

- فراخوانی DLL با Reflection انجام می‌شود (`Intek.PcPosLibrary.PcPos`)، بنابراین اگر
  نام متدها در نسخهٔ شما متفاوت بود کافی است در `PosDevice.cs` نام متد/پراپرتی درست
  را اضافه کنید (`Purchase` / `StartTransaction` / `Sale`).
- مبلغ همیشه به **ریال** به دستگاه فرستاده می‌شود؛ وب‌اپ مبلغ تومانی را ×۱۰ می‌کند.
- سرویس فقط روی لوپ‌بک گوش می‌دهد و از بیرون شبکه در دسترس نیست.
- آدرس سرویس و شمارهٔ ترمینال از پنل مدیریت → «کارت‌خوان» قابل تغییر و تست است.

## حالت اتصال شبکه (LAN) — پیش‌فرض

`appsettings.json`:

```json
{
  "connectionMode": "lan",
  "deviceIp": "192.168.1.100",
  "devicePort": 8888,
  "merchantId": "6618774",
  "terminalId": "5634056"
}
```

مسیرهای سرویس:

| مسیر | توضیح |
| --- | --- |
| `GET /health` | وضعیت سرویس + وضعیت واقعی اتصال به دستگاه (`device.connected`) |
| `GET /config` / `POST /config` | خواندن و تغییر تنظیمات از پنل مدیریت (در فایل ذخیره می‌شود) |
| `GET /discover?port=8888` | اسکن زیرشبکهٔ محلی و برگرداندن IPهای پاسخ‌گو |
| `POST /pay` | شروع تراکنش فروش |
| `POST /cancel` | لغو تراکنش جاری |

اگر `pec.pcpos.dll` کنار فایل اجرایی باشد از همان استفاده می‌شود؛ در غیر این صورت در
حالت شبکه ارتباط مستقیم TCP با دستگاه برقرار می‌گردد
(`STX|merchantId|terminalId|amountRial|invoice|PURCHASE|ETX` و پاسخ `code|rrn|pan`).

### مسیرهای تشخیصی جدید

| مسیر | توضیح |
| --- | --- |
| `GET /ping?ip=&port=&timeout=` | اتصال TCP + handshake با اندازه‌گیری زمان پاسخ؛ خروجی `ok`, `stage`, `latencyMs`, `message` |
| `GET /logs?after=<id>` | رویدادهای بعد از شناسهٔ داده‌شده (fallback وقتی SSE کار نکند) |
| `POST /logs` | پاک کردن لاگ |
| `GET /events` | استریم SSE رویدادها (`log`) و وضعیت دستگاه هر ۵ ثانیه (`status`) |

`serialNumber` و `devicePassword` در `appsettings.json` نگهداری می‌شوند؛ `devicePassword` فقط
سمت سرویس می‌ماند و در پاسخ‌های HTTP یا لاگ‌ها ظاهر نمی‌شود.

## اتصال واقعی با کتابخانهٔ رسمی (PosInterface.dll)

از این نسخه، پرداخت با کتابخانهٔ رسمی PC-POS انجام می‌شود:

- فایل `lib/PosInterface.dll` همراه پروژه است و در `PosBridge.csproj` رفرنس شده.
- سرویس روی پورت `posListenPort` (پیش‌فرض **17000**) گوش می‌دهد؛ دستگاه باید در منوی
  خود روی حالت PC-POS با IP همین کیوسک و همین پورت تنظیم شود.
- اتصال شبکه‌ای با `InitLAN(deviceIp)` و اتصال USB با `InitSerial(comPort, baudRate)` برقرار می‌شود.
- نتیجهٔ تراکنش (کد پاسخ، RRN، شمارهٔ کارت ماسک‌شده، Stan) از رویداد `OnTransactionDone` خوانده می‌شود.
- اگر کتابخانه پاسخ ندهد، به‌صورت خودکار پروتکل مستقیم TCP امتحان می‌شود.

## چاپ بلیط روی پرینتر حرارتی ۸۰ میلی‌متری

سرویس دو مسیر جدید دارد:

| مسیر | متد | کاربرد |
| --- | --- | --- |
| `/printers` | GET | فهرست پرینترهای نصب‌شده در ویندوز + پرینتر پیش‌فرض |
| `/print` | POST | چاپ بلیط (متن فارسی راست‌به‌چپ + کد QR ورود) |

نمونهٔ بدنهٔ `/print`:

```json
{
  "invoiceNumber": "INV-20260827-1234",
  "dateTime": "۶ شهریور ۱۴۰۵، ۱۰:۳۰",
  "paymentMethod": "card",
  "totalToman": 450000,
  "refNumber": "123456789012",
  "maskedPan": "6221-****-****-1234",
  "terminalId": "5634056",
  "items": [{ "name": "بلیط بزرگسال", "quantity": 2, "totalToman": 300000 }],
  "qrPng": "data:image/png;base64,..."
}
```

تصویر QR در خود کیوسک ساخته و به‌صورت PNG ارسال می‌شود؛ متن فارسی با فونت ویندوز
(`printerFont`، پیش‌فرض Tahoma) و به‌صورت گرافیکی چاپ می‌شود تا روی همهٔ پرینترهای
حرارتی درست دیده شود. پرینتر و فعال/غیرفعال بودن چاپ خودکار از صفحهٔ
«تنظیمات کارت‌خوان» در پنل مدیریت قابل تغییر است.
