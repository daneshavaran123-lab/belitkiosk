# سرویس پل کارت‌خوان (PosBridge)

مرورگر کیوسک نمی‌تواند مستقیماً با کارت‌خوان صحبت کند. این سرویس کوچک ویندوزی روی همان کیوسک
اجرا می‌شود، فقط روی `127.0.0.1` گوش می‌دهد و درخواست پرداخت وب‌اپ را با پروتکل **PC-POS** به
دستگاه (PAX Q58 و مشابه) می‌فرستد.

```text
کیوسک (وب‌اپ) --HTTP--> PosBridge (127.0.0.1:9099) --TCP 17000--> کارت‌خوان (192.168.16.160)
                                   ^                                   |
                                   +------ پاسخ (همان اتصال یا اتصال برگشتی به 17000) ---+
```

## پروتکل PC-POS (تأییدشده با خود PosInterface.dll)

قالب زیر با اجرای واقعی `lib/PosInterface.dll` (کتابخانهٔ رسمی)، ضبط بایت‌هایی که روی شبکه
می‌فرستد و خواندن پارسر پاسخ آن به دست آمده و سرویس دقیقاً همان را می‌سازد:

```text
درخواست:  $PCBUY,<مبلغ ریال>,<شمارهٔ فاکتور>,<yyyyMMddHHmmss>,<MessageId>,0,<pcposAppId>,*<XOR>\r\n
نمونه:    $PCBUY,10000,12345,20261026120000,1,0,,*70\r\n

پاسخ:     $POSBUY,<کد>,<مبلغ>,<RRN>,<STAN>,<تاریخ>,<پذیرنده>,<پایانه>,<کارت>,<MessageId>,*<XOR>\r\n
```

- چک‌سام = XOR همهٔ بایت‌های بین `$` و `*`، دو رقم هگز بزرگ.
- بعد از آخرین فیلد یک `,` اضافه می‌آید که در چک‌سام حساب می‌شود (اسکریپت‌های دستی معمولاً آن را
  جا می‌اندازند و دستگاه ممکن است با کد ۴۱۲ رد کند).
- تاریخ همیشه **میلادی** است؛ روی ویندوز فارسی `Get-Date -Format yyyy` سال شمسی می‌دهد.
- فیلد `0` تعداد حساب‌های تسهیم است. شمارهٔ فاکتور فقط رقم است.
- کد پاسخ `0` یعنی موفق. جدول کدها (از خود کتابخانه):

| کد | معنی | کد | معنی |
| --- | --- | --- | --- |
| 0 | تراکنش موفق | 84 | بانک صادرکننده پاسخ نمی‌دهد |
| 3 | پذیرندهٔ نامعتبر | 400 | پاسخی از سوئیچ نرسید |
| 5 | از تراکنش صرف‌نظر شد | 402 | ارتباط با سوئیچ برقرار نیست |
| 12 | تراکنش نامعتبر | 412 | دستگاه درخواست را نتوانست بخواند |
| 51 | موجودی کافی نیست | 501 | پیش‌نیازهای دستگاه (ورود/تسویه) انجام نشده |
| 55 | رمز کارت نادرست | 502 | لغو توسط کاربر |
| 56 | کارت نامعتبر | 777 | پایان زمان انتظار |
| 61 | مبلغ بیش از حد مجاز | | |

### دو روش برگشت پاسخ (`responseMode`)

| مقدار | رفتار |
| --- | --- |
| `auto` (پیش‌فرض) | هم روی همان اتصال و هم با اتصال برگشتی منتظر پاسخ می‌ماند — با هر دو تنظیم دستگاه کار می‌کند |
| `callback` | مثل پیش‌فرض کتابخانهٔ رسمی: بعد از ارسال، کیوسک روی پورت 17000 منتظر می‌ماند تا **دستگاه** وصل شود |
| `same` | پاسخ روی همان اتصال TCP درخواست می‌آید (`ResponseConnectionMode = true` در کتابخانه) |

در حالت‌های `auto` و `callback` کارت‌خوان باید بتواند به پورت 17000 کیوسک وصل شود؛
`tools\allow-firewall.bat` را **با دسترسی Administrator** اجرا کنید (قاعده فقط IP خود کارت‌خوان را
می‌پذیرد). اگر فایروال بسته باشد، پول کسر می‌شود ولی کیوسک پاسخی نمی‌بیند.

## نصب

پیش‌نیاز: ویندوز ۱۰/۱۱ و .NET SDK 8 (خروجی روی .NET Framework 4.8 اجرا می‌شود؛ Developer Pack لازم نیست).

```bat
cd pos-bridge
dotnet build -c Release
tools\allow-firewall.bat          :: با Run as administrator
run.bat                           :: در Startup بگذارید؛ اگر سرویس بسته شود خودکار دوباره اجرا می‌شود
```

مهم‌ترین کلیدهای `appsettings.json`:

| کلید | پیش‌فرض | توضیح |
| --- | --- | --- |
| `deviceIp` / `devicePort` | `192.168.16.160` / `17000` | آدرس PC-POS روی کارت‌خوان |
| `protocol` | `native` | `native` = پیاده‌سازی مستقیم، `sdk` = کتابخانهٔ رسمی (برای USB/سریال هم خودکار `sdk`) |
| `responseMode` | `auto` | جدول بالا |
| `accessToken` | خالی | **حتماً** یک رشتهٔ تصادفی طولانی بگذارید و همان را در پنل کارت‌خوان وارد کنید |
| `allowedOrigins` | آدرس کیوسک | فقط این صفحه‌ها (و `http://127.0.0.1:*` برنامهٔ دسکتاپ) اجازهٔ تماس دارند |
| `timeoutSeconds` | `120` | حداکثر انتظار برای کارت و رمز |
| `cancelGraceSeconds` | `20` | بعد از لغو در کیوسک چقدر منتظر نتیجهٔ نهایی دستگاه بماند |
| `lateResponseSeconds` | `180` | تا کی پاسخ دیرهنگام ثبت شود |
| `maxAmountRial` | `1000000000` | سقف یک تراکنش |
| `requireRrn` | `true` | تأیید بدون شمارهٔ مرجع پذیرفته نمی‌شود |
| `pcposAppId` | خالی | فیلد آخر درخواست؛ کتابخانهٔ رسمی خالی می‌فرستد |
| `journalPath` | `data/transactions.jsonl` | دفتر تراکنش‌ها |
| `simulate` | `false` | تست کامل جریان بدون دستگاه |

## ایمنی پرداخت

- **بدون کسر دوباره:** هر پرداخت یک `transactionId` دارد؛ درخواست تکراری با همان شناسه نتیجهٔ قبلی را
  برمی‌گرداند. تلاش دوباره فقط برای «اتصال» و پیش از ارسال است؛ بعد از ارسال حتی یک بایت، درخواست
  هرگز دوباره فرستاده نمی‌شود. هم‌زمان فقط یک پرداخت روی دستگاه انجام می‌شود.
- **پاسخ فقط وقتی پذیرفته می‌شود که** چک‌سام درست باشد و MessageId، مبلغ، شمارهٔ پایانه و RRN با
  درخواست بخوانند و RRN قبلاً برای تراکنش دیگری ثبت نشده باشد. در غیر این صورت تراکنش «نامطمئن»
  است و بلیط صادر نمی‌شود.
- **اتصال برگشتی** فقط از IP خود کارت‌خوان پذیرفته می‌شود.
- **پول گم نمی‌شود:** دفتر تراکنش‌ها روی دیسک است. اگر مرورگر رفرش شود نتیجه از `/status` خوانده
  می‌شود؛ اگر سرویس وسط تراکنش بسته شود، پس از اجرای دوباره تراکنش «نیازمند بررسی» می‌شود؛ تأییدی
  که بعد از لغو یا پایان زمان برسد به‌صورت `approved_late` ثبت می‌شود.
- **لغو:** پروتکل فرمان لغو ندارد. کیوسک لغو را ثبت می‌کند و تا `cancelGraceSeconds` منتظر نتیجهٔ
  واقعی می‌ماند (اگر مشتری همان لحظه پرداخته باشد، فروش ثبت می‌شود). برای لغو فوری روی خود دستگاه
  دکمهٔ قرمز را بزنید.
- شمارهٔ کارت فقط ماسک‌شده (۶ رقم اول و ۴ رقم آخر) ذخیره، لاگ و نمایش داده می‌شود.

تراکنش‌های «نیازمند بررسی» در پنل مدیریت → «تنظیمات کارت‌خوان» → «دفتر تراکنش‌های کارت‌خوان»
دیده می‌شوند. آن‌ها را با رسید دستگاه یا گزارش بانک تطبیق دهید و پس از بازگشت وجه یا صدور دستی بلیط
«بررسی شد» بزنید.

## امنیت سرویس

- فقط روی `127.0.0.1` گوش می‌دهد (`listenUrl` دیگری پذیرفته نمی‌شود).
- درخواست مرورگر از هر Origin خارج از `allowedOrigins` **پیش از هر کاری** با ۴۰۳ رد می‌شود؛ یعنی
  هیچ سایت دیگری که در مرورگر کیوسک باز شود نمی‌تواند پرداخت بسازد یا IP دستگاه را عوض کند.
- با `accessToken` همهٔ مسیرها به‌جز `/health` توکن می‌خواهند (مقایسهٔ زمان‌ثابت). توکن و رمزها از
  طریق HTTP قابل خواندن یا تغییر نیستند.
- بدنهٔ درخواست‌ها محدودیت حجم و نوع (`application/json`) دارد و ورودی‌ها اعتبارسنجی می‌شوند.

## مسیرهای HTTP

| متد | مسیر | توضیح |
| --- | --- | --- |
| GET | `/health` | وضعیت سرویس و دستگاه (بدون توکن) |
| POST | `/pay` | `{ transactionId, amountRial, amountToman?, invoiceNumber }` ← نتیجهٔ نهایی |
| GET | `/status?id=` | وضعیت یک تراکنش (برای بازیابی) |
| POST | `/cancel` | `{ transactionId }` درخواست لغو |
| GET | `/transactions?limit=` | دفتر تراکنش‌ها و تعداد موارد نیازمند بررسی |
| POST | `/transactions/review` | `{ transactionId, note }` علامت «بررسی شد» |
| GET/POST | `/config` | خواندن/تغییر تنظیمات (توکن و رمزها فقط از فایل) |
| GET | `/ping` | فقط اتصال TCP به دستگاه (هیچ داده‌ای فرستاده نمی‌شود) |
| GET | `/discover` | پیدا کردن دستگاه‌هایی که پورت PC-POS آن‌ها باز است |
| GET | `/logs`، `/events` | لاگ و استریم زنده برای پنل |
| GET/POST | `/printers`، `/print` | چاپ بلیط روی پرینتر حرارتی |

نمونهٔ پاسخ `/pay`:

```json
{
  "transactionId": "4b0c…", "success": true, "status": "approved", "final": true,
  "uncertain": false, "responseCode": "0", "refNumber": "123456789012",
  "stan": "654321", "maskedPan": "603799******1234", "terminalId": "5634056", "message": "تراکنش موفق"
}
```

## تست

- **بدون دستگاه:** `"simulate": true`.
- **آزمون‌های خودکار:** `dotnet test tests/PosBridge.Tests` (بردارهای طلایی ضبط‌شده از کتابخانهٔ
  رسمی، پارسر، دفتر تراکنش و سناریوهای شبکه با دستگاه ساختگی).
- **مستقیم با دستگاه واقعی** (بدون کیوسک؛ اول PosBridge را ببندید):

  ```powershell
  powershell -ExecutionPolicy Bypass -File tools\Test-PcPos.ps1 -Amount 10000
  # اگر دستگاه پاسخ را روی همان اتصال می‌دهد:
  powershell -ExecutionPolicy Bypass -File tools\Test-PcPos.ps1 -Amount 10000 -ResponseMode Same
  ```

  این یک **خرید واقعی** است (مبلغ به ریال).

## عیب‌یابی

| نشانه | علت محتمل | راه‌حل |
| --- | --- | --- |
| دستگاه رسید چاپ کرد ولی کیوسک «بی‌پاسخ» گفت | فایروال پورت 17000 را بسته | `tools\allow-firewall.bat` با Administrator |
| «پورت 17000 آزاد نیست» | PosAgent یا نسخهٔ دیگری از سرویس در حال اجراست | آن را ببندید، یا `responseMode` را `same` بگذارید |
| کد ۴۱۲ | قالب درخواست را دستگاه نخواند | با `Test-PcPos.ps1` تست کنید؛ `pcposAppId` را خالی بگذارید |
| کد ۵۰۱ | دستگاه پیش‌نیاز (ورود/تسویه) دارد | روی دستگاه ورود/تسویه انجام دهید |
| ۴۰۳ در کیوسک | آدرس صفحه در `allowedOrigins` نیست | آدرس دقیق (مثل `https://….lovable.app`) را اضافه کنید |
| ۴۰۱ در کیوسک | توکن پنل با `accessToken` یکی نیست | توکن را در پنل کارت‌خوان دوباره وارد کنید |
