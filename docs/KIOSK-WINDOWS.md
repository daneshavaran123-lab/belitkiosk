# راهنمای نصب کیوسک ویندوزی — Windows Kiosk Guide

نسخهٔ کیوسک این پروژه یک **PWA** است که در حالت `--kiosk` مرورگر Chrome/Edge روی یک
مانیتور لمسی **۱۰۸۰×۱۹۲۰ عمودی** اجرا می‌شود. هیچ نصب اپلیکیشن جداگانه‌ای لازم نیست.

---

## ۰. پیش‌نیازها

| مورد | حداقل |
|---|---|
| سیستم‌عامل | Windows 10 (نسخه 1909) یا Windows 11 |
| مرورگر | Google Chrome ۱۲۰+ (یا Microsoft Edge ۱۲۰+) |
| صفحه‌نمایش | مانیتور لمسی ۱۰۸۰×۱۹۲۰ (Portrait) |
| شبکه | اینترنت پایدار (اپ آفلاین کار نمی‌کند) |
| حساب ویندوز | یک حساب محلی مخصوص کیوسک، بدون دسترسی Administrator |

---

## ۱. چرخاندن صفحه به حالت عمودی

1. راست‌کلیک روی دسکتاپ → **Display settings**
2. **Display resolution** → `1080 × 1920`
3. **Display orientation** → `Portrait`
4. **Apply** → **Keep changes**

> اگر مانیتور فیزیکی چرخانده شده، ممکن است لازم باشد `Portrait (flipped)` را انتخاب کنید.

### کالیبراسیون لمس

`Control Panel → Tablet PC Settings → Setup` و دستورالعمل روی صفحه را دنبال کنید.
بدون کالیبراسیون بعد از چرخاندن صفحه، محل لمس با محل نمایش جابه‌جا خواهد بود.

---

## ۲. اجرای کیوسک

### روش الف — اسکریپت آماده (پیشنهادی)

فایل [`scripts/launch-kiosk.bat`](../scripts/launch-kiosk.bat) در همین مخزن موجود است.

1. فایل را روی دسکتاپ کیوسک کپی کنید.
2. با Notepad بازش کنید و خط زیر را با آدرس منتشرشدهٔ خودتان جایگزین کنید:
   ```bat
   set "KIOSK_URL=https://project--<your-id>.lovable.app"
   ```
3. دوبار کلیک کنید.

### روش ب — شورتکات دستی

راست‌کلیک روی دسکتاپ → **New → Shortcut** و در فیلد مسیر این را بگذارید (همه در یک خط):

```
"C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk --user-data-dir="%LOCALAPPDATA%\MuseumKiosk\ChromeProfile" --window-size=1080,1920 --window-position=0,0 --no-first-run --no-default-browser-check --disable-pinch --overscroll-history-navigation=0 --disable-features=TranslateUI --disable-session-crashed-bubble --disable-infobars --touch-events=enabled https://project--<your-id>.lovable.app
```

### توضیح فلگ‌ها

| فلگ | کارکرد |
|---|---|
| `--kiosk` | تمام‌صفحه بدون نوار آدرس، بدون تب |
| `--user-data-dir` | پروفایل جدا؛ تاریخچه و کش کیوسک از مرورگر عادی جدا می‌ماند |
| `--disable-pinch` | جلوگیری از زوم دو انگشتی توسط بازدیدکننده |
| `--overscroll-history-navigation=0` | جلوگیری از «کشیدن به عقب» و خروج از صفحه |
| `--disable-session-crashed-bubble` | حذف پیام «Restore pages?» پس از قطع برق |
| `--disable-infobars` | حذف نوارهای هشدار بالای صفحه |
| `--check-for-update-interval` | کاهش تعداد ری‌استارت‌های ناخواستهٔ آپدیت |

## ۳. اجرای خودکار با روشن شدن ویندوز

1. `Win + R` → تایپ کنید `shell:startup` → Enter
2. یک **شورتکات** از `launch-kiosk.bat` را داخل این پوشه بگذارید.
3. برای ورود خودکار بدون رمز: `Win + R` → `netplwiz` → تیک
   *Users must enter a user name and password* را بردارید.

---

## ۴. قفل کردن دستگاه (Hardening)

| هدف | مسیر |
|---|---|
| خاموش‌نشدن صفحه | Settings → System → Power → Screen and sleep → **Never** |
| حذف Screen saver | Control Panel → Personalization → Screen Saver → **(None)** |
| قطع نوتیفیکیشن‌ها | Settings → System → Notifications → **Off** / Focus assist |
| توقف ری‌استارت آپدیت | Settings → Windows Update → Active hours = تمام ساعات کاری |
| غیرفعال کردن کلید Windows | با ابزار `SharpKeys` یا Group Policy |
| غیرفعال کردن Task Manager | `gpedit.msc` → User Configuration → Administrative Templates → System → Ctrl+Alt+Del Options |
| مخفی کردن Taskbar | راست‌کلیک روی taskbar → Taskbar settings → Automatically hide |

### حالت Assigned Access (سخت‌گیرانه‌تر)

Windows 11 Pro قابلیت **Kiosk mode** بومی دارد:
`Settings → Accounts → Other users → Set up a kiosk` → انتخاب Microsoft Edge →
`Public browsing (InPrivate)` → وارد کردن URL و آیدل تایم‌اوت.
در این حالت کاربر اصلاً به دسکتاپ دسترسی ندارد.

## ۵. خروج اضطراری

| روش | توضیح |
|---|---|
| `Alt + F4` | بستن پنجرهٔ کیوسک |
| `Ctrl + Alt + Del` → Task Manager | پایان دادن به فرایند chrome.exe |
| `Ctrl + W` | فقط اگر kiosk mode را غیرفعال کرده باشید |

پیشنهاد می‌شود کلیدهای بالا با Group Policy فقط برای حساب کیوسک غیرفعال شوند و
پرسنل برای نگهداری با یک حساب Administrator جداگانه وارد شوند.

## ۶. نصب به‌عنوان اپ (PWA) روی دسکتاپ

اگر ترجیح می‌دهید آیکن اپ روی دسکتاپ باشد به‌جای شورتکات مرورگر:

1. آدرس اپ را در Chrome باز کنید.
2. منوی سه‌نقطه → **Cast, save, and share → Install page as app…**
3. اپ در `Start Menu` با آیکن موزه ظاهر می‌شود و بدون نوار آدرس باز می‌شود.
4. برای اجرای خودکار: `chrome://apps` → راست‌کلیک روی اپ → **Create shortcut**
   و شورتکات را در `shell:startup` بگذارید.

مانيفست اپ (`public/manifest.webmanifest`) با `display: fullscreen` و
`orientation: portrait` تنظیم شده تا در حالت نصب‌شده هم تمام‌صفحه و عمودی باشد.

> **توجه:** فیلدهای `start_url`, `scope`, `id`, `display` هنگام نصب کش می‌شوند.
> اگر بعداً تغییرشان دادید، باید اپ روی کیوسک حذف و دوباره نصب شود.

## ۷. رفرش شبانه (اختیاری ولی توصیه‌شده)

برای اینکه هر شب آخرین نسخه و حافظهٔ تمیز لود شود:

1. `taskschd.msc` را باز کنید → **Create Basic Task**
2. نام: `Museum Kiosk Restart`، Trigger: **Daily** ساعت `04:00`
3. Action: **Start a program** → `powershell.exe`
   Arguments:
   ```
   -NoProfile -Command "Stop-Process -Name chrome,msedge -Force -ErrorAction SilentlyContinue; Start-Sleep 5; Start-Process 'C:\kiosk\launch-kiosk.bat'"
   ```

## ۸. عیب‌یابی کیوسک

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| صفحه اسکرول می‌خورد | زوم مرورگر ≠ ۱۰۰٪ | `Ctrl + 0` یا حذف `--force-device-scale-factor` |
| محتوا بریده می‌شود | رزولوشن ≠ 1080×1920 | Display settings را دوباره تنظیم کنید |
| لمس در جای اشتباه | کالیبراسیون بعد از چرخاندن انجام نشده | `Tablet PC Settings → Setup` |
| کیبورد مجازی باز نمی‌شود | سرویس خاموش است | `services.msc` → **Touch Keyboard and Handwriting Panel Service** → Automatic |
| پیام «Restore pages?» | خاموشی ناگهانی | فلگ `--disable-session-crashed-bubble` (در اسکریپت هست) |
| صفحهٔ سفید بعد از انتشار جدید | کش مرورگر | `Ctrl + Shift + R`، یا پاک کردن پوشهٔ پروفایل کیوسک |
| کیوسک با ویندوز بالا نمی‌آید | شورتکات در startup نیست | `shell:startup` را چک کنید |
| بدون اینترنت خطا می‌دهد | اپ آفلاین ندارد | اتصال شبکه/Wi‑Fi را پایدار کنید |

## ۹. طراحی no-scroll — چطور کار می‌کند

- `html, body` در `src/styles.css` روی `overflow: hidden` و `height: 100%` قفل شده‌اند.
- هر صفحهٔ عمومی از `.kiosk-root` (فلکس عمودی، `100dvh`) استفاده می‌کند:
  header و footer ثابت می‌مانند.
- محتوای میانی داخل `.kiosk-body` است: `flex-1; min-height: 0; overflow-y: auto`
  با اسکرول‌بار مخفی — یعنی اگر روی صفحهٔ کوچک‌تر محتوا جا نشد، فقط همان ناحیه
  اسکرول می‌شود، نه کل صفحه.
- اندازهٔ فونت پایه با media query تنظیم می‌شود:
  `20px` برای ارتفاع ≥۱۴۰۰px و `24px` برای ≥۱۸۰۰px (کیوسک عمودی)،
  `14px` برای لپ‌تاپ‌های کوتاه.

اگر یک صفحهٔ جدید ساختید، آن را داخل `PageShell` بگذارید تا این رفتار خودکار اعمال شود.

## کارت‌خوان روی کیوسک

1. `pec.pcpos.dll` را در `pos-bridge/lib/` بگذارید و `dotnet build -c Release` را اجرا کنید.
2. `pos-bridge/appsettings.json` را با پورت COM دستگاه و شمارهٔ ترمینال (`5634056`) تنظیم کنید.
3. `pos-bridge/run.bat` را در Task Scheduler برای «اجرا هنگام ورود کاربر» ثبت کنید تا سرویس
   قبل از مرورگر بالا بیاید.
4. در پنل مدیریت → «کارت‌خوان» دکمهٔ «تست اتصال» باید وضعیت «متصل» بدهد.
5. سرویس فقط روی `127.0.0.1` گوش می‌دهد؛ نیازی به باز کردن پورت در فایروال شبکه نیست.

## تنظیم نمایشگر ۱۰۸۰×۱۹۲۰ (مقیاس ۱۰۰٪)

نمایشگر کیوسک باید دقیقاً روی این مقادیر باشد تا صفحه بدون اسکرول و در اندازهٔ درست دیده شود:

1. کلیک راست روی دسکتاپ → **Display settings**
2. **Scale and layout → Change the size of text, apps…** = **100%**
   (اگر روی ۱۷۵٪ است حتماً به ۱۰۰٪ تغییر دهید؛ در غیر این صورت فقط بخشی از صفحه دیده می‌شود.)
3. **Display resolution** = **1080 × 1920**
4. **Display orientation** = **Portrait**
5. یک‌بار Sign out / Sign in کنید تا مقیاس کامل اعمال شود.
6. `scripts\launch-kiosk.bat` را دوباره اجرا کنید. این اسکریپت با
   `--force-device-scale-factor=1` اجرا می‌شود، بنابراین حتی اگر مقیاس ویندوز
   عوض شود، اندازهٔ کیوسک ثابت می‌ماند.

اگر باز هم صفحه بزرگ/کوچک بود: در کیوسک `Ctrl + 0` بزنید تا زوم مرورگر روی ۱۰۰٪ برگردد.

## اتصال کارت‌خوان PAX Q58 روی شبکه

1. روی خود کارت‌خوان: **منو → تنظیمات → شبکه** و IP دستگاه را یادداشت کنید
   (کیوسک و کارت‌خوان باید روی یک شبکه/سوییچ باشند).
2. سرویس `pos-bridge` را روی کیوسک اجرا کنید (`pos-bridge\run.bat`).
3. در برنامه وارد **پنل مدیریت → تنظیمات کارت‌خوان** شوید:
   - نوع اتصال: **شبکه (LAN / IP)**
   - IP دستگاه و پورت (پیش‌فرض `8888`)
   - کد پذیرنده `6618774` و کد پایانه `5634056`
   - **ذخیره و اعمال** و سپس **تست اتصال**
4. اگر IP را نمی‌دانید، دکمهٔ **جست‌وجوی خودکار در شبکه** کل زیرشبکه را روی همان پورت اسکن می‌کند.

خطاهای رایج:

| پیام | علت | راه‌حل |
| --- | --- | --- |
| سرویس کارت‌خوان در دسترس نیست | `pos-bridge` اجرا نشده | `pos-bridge\run.bat` را اجرا کنید |
| دستگاه در آدرس …:8888 پاسخ نمی‌دهد | IP اشتباه یا شبکهٔ متفاوت | IP را از منوی دستگاه بگیرید یا اسکن خودکار بزنید |
| تراکنش ناموفق (کد …) | پاسخ منفی پایانه | کد پاسخ را روی خود دستگاه بررسی کنید |

## دکمهٔ «شروع اتصال» و عیب‌یابی مرحله‌به‌مرحله

در **پنل مدیریت → تنظیمات کارت‌خوان** دکمهٔ «شروع اتصال» پنج مرحله را پشت سر هم اجرا می‌کند
و زمان پاسخ هر مرحله را نشان می‌دهد:

| مرحله | یعنی چه | اگر قرمز شد |
| --- | --- | --- |
| سرویس پل روی کیوسک | `pos-bridge` در حال اجراست | `pos-bridge\run.bat` را اجرا کنید |
| ارسال تنظیمات به سرویس | IP/پورت/کدها ذخیره شد | مقادیر فرم را بررسی کنید |
| پیدا شدن دستگاه در شبکه | پورت دستگاه باز است | IP اشتباه، دستگاه خاموش یا شبکهٔ متفاوت |
| دست‌دهی با کارت‌خوان | دستگاه به بستهٔ تست پاسخ داد | دستگاه را روی صفحهٔ اصلی/آماده بگذارید |
| آماده دریافت پرداخت | همه‌چیز درست است | — |

- **بازآزمایی خودکار:** بعد از قطع شدن، خودکار با فاصلهٔ ۲، ۴، ۸، ۱۶ و سپس هر ۳۰ ثانیه تلاش
  می‌شود و شمارهٔ تلاش و شمارش معکوس روی صفحه دیده می‌شود. با دکمهٔ «توقف بازآزمایی» خاموش می‌شود.
- **تنظیم دستی:** IP و پورت را دستی وارد کنید و «تأیید همین آدرس» را بزنید؛ بدون ذخیره‌سازی فقط
  همان آدرس تست می‌شود.
- **لاگ زنده:** پایین صفحه رویدادهای سرویس پل به‌صورت لحظه‌ای (SSE، و در صورت نبود، هر ۲ ثانیه)
  نمایش داده می‌شود و با دکمهٔ کپی می‌توان آن را برای پشتیبانی فرستاد.

## قفل صفحهٔ کارت‌خوان، توکن سرویس و گزارش پشتیبانی

**قفل صفحه:** ورود به `/admin/pos` علاوه بر حساب مدیر، یک بار وارد کردن دوبارهٔ رمز همان حساب
را می‌خواهد. قفل ۸ ساعت روی همان مرورگر باز می‌ماند و با دکمهٔ «قفل کردن دوباره» بسته می‌شود؛
با بستن مرورگر هم قفل برمی‌گردد.

**توکن سرویس پل:** در `pos-bridge\appsettings.json` مقدار `accessToken` را روی یک رشتهٔ تصادفی
بگذارید. از آن پس مسیرهای `/config`، `/logs` و `/events` بدون هدر `X-Pos-Token` (یا پارامتر
`?token=` برای استریم) با ۴۰۱ رد می‌شوند. همان مقدار را در کادر «توکن دسترسی سرویس پل» در صفحهٔ
کارت‌خوان وارد و ذخیره کنید. خالی گذاشتن `accessToken` یعنی بدون محدودیت (فقط برای تست).

**ماندگاری اتصال:** IP، پورت، حالت اتصال، آخرین وضعیت، آخرین زمان پاسخ و آخرین خطا در مرورگر
کیوسک ذخیره می‌شوند؛ بعد از رفرش یا ریبوت فقط یک ping سریع به همان IP زده می‌شود و اسکن کامل
شبکه تنها وقتی اجرا می‌شود که آدرس ذخیره‌شده جواب ندهد.

**بازگشت از پس‌زمینه:** با رویدادهای `visibilitychange`، `focus` و `online` اگر دستگاه قطع بوده
باشد همان زنجیرهٔ backoff (۲، ۴، ۸، ۱۶، ۳۰ ثانیه) از تلاش اول شروع می‌شود و پیام «در حال اتصال…»
با شمارهٔ تلاش نمایش داده می‌شود؛ اگر متصل بوده فقط یک ping سلامت زده می‌شود.

**گزارش پشتیبانی:** دکمهٔ «دانلود گزارش» یک فایل متنی (به‌همراه بخش JSON) می‌سازد شامل آخرین ۱۰
تلاش ping/handshake، رویدادهای سرویس پل، کد پذیرنده/پایانه/سریال، IP و پورت، و مشخصات کیوسک
(ویندوز ۱۰ Enterprise 22H2 build 19045، Core i5-7500، ۸ گیگ رم، نمایشگر ۱۰۸۰×۱۹۲۰ عمودی، لمسی
۱۰ نقطه، نسخهٔ مرورگر). رمز دستگاه و توکن دسترسی هرگز داخل گزارش نوشته نمی‌شوند. دکمهٔ «کپی
گزارش» همان متن را برای ارسال در پیام‌رسان کپی می‌کند.

## پیش‌نیاز PosAgent (روش پیشنهادی پرداخت)

اگر روش اتصال روی **PosAgent** تنظیم شده باشد (پیش‌فرض):

1. سرویس PosAgent باید روی همان رایانهٔ کیوسک نصب و اجرا باشد:
   `net start PosAgentService` (برای اجرای خودکار، Startup type را روی Automatic بگذارید).
2. سرویس روی `http://127.0.0.1:18765` (HTTP) و `ws://127.0.0.1:18766` (WebSocket) گوش می‌دهد؛
   فقط localhost است و نیازی به باز کردن فایروال ندارد.
3. سلامت سرویس در پنل مدیریت → «کارت‌خوان» → کارت «سرویس پرداخت PosAgent» با دکمهٔ «بررسی دوباره»
   قابل مشاهده است. اگر «خارج از دسترس» بود، سرویس اجرا نشده است.
4. چاپ بلیط همچنان به pos-bridge نیاز دارد؛ پس هر دو سرویس باید در استارتاپ باشند.
