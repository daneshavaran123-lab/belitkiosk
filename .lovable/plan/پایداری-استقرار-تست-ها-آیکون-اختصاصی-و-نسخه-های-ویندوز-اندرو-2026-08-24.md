# پایداری استقرار، تست‌ها، آیکون اختصاصی و نسخه‌های ویندوز/اندروید

## ۱. Endpoint سلامت سرویس
- مسیر `GET /api/public/health` (بدون احراز هویت، قابل فراخوانی از لیارا و مانیتورینگ) و یک alias ساده `/api/health`.
- خروجی JSON: وضعیت `ok`، زمان سرور، نسخهٔ برنامه، `uptime`، و نتیجهٔ یک پینگ سبک به دیتابیس (`db: "ok" | "down"`) بدون افشای کلید یا آدرس داخلی.
- `healthCheck` در `liara.json` به همین مسیر تغییر می‌کند.

## ۲. لاگ دقیق زمان استارت
- یک ماژول startup-log که هنگام بالا آمدن سرور یک بار چاپ می‌کند: HOST، PORT، حالت اجرا (production/dev)، preset بیلد، و وضعیت متغیرهای Supabase (فقط «تنظیم‌شده/تنظیم‌نشده» — نه مقدار).
- در همان لاگ، اگر `PORT` تعریف نشده باشد یا HOST غیر از `0.0.0.0` باشد هشدار واضح چاپ می‌شود تا خطای listen لیارا سریع تشخیص داده شود.
- اسکریپت `start` طوری اصلاح می‌شود که مقدار نهایی host/port قبل از اجرای سرور در لاگ دیده شود.

## ۳. تست‌های end-to-end پرداخت کارت‌خوان
- افزودن Vitest + یک ماک سرویس pos-bridge (سرور HTTP محلی) تا بدون دستگاه واقعی قابل اجرا باشد.
- سناریوها:
  - پرداخت موفق → ثبت فاکتور + اقلام + کد پیگیری و شمارهٔ کارت روی رسید.
  - پاسخ ناموفق دستگاه → عدم ثبت فاکتور و نمایش پیام خطا.
  - در دسترس نبودن سرویس پل / timeout / لغو تراکنش → پیام مناسب و بازگشت به سبد.
  - خطای ثبت فاکتور با وجود پرداخت موفق → نمایش هشدار «کد پیگیری را یادداشت کنید».
- تست‌ها روی توابع `src/lib/pos.ts` و منطق ثبت فاکتور (که به یک ماژول قابل‌تست جدا می‌شود) اجرا می‌شوند؛ لایهٔ دیتابیس ماک می‌شود.
- افزودن اسکریپت‌های `test` و `test:run` و یک workflow گیت‌هاب (`.github/workflows/ci.yml`) که lint + typecheck + test + build را اجرا می‌کند.

## ۴. اسکریپت smoke test بعد از deploy
- `scripts/smoke-test.mjs` با ورودی `BASE_URL`:
  - بررسی `/api/health`
  - بررسی وضعیت ۲۰۰ و وجود محتوای کلیدی در `/`، `/tickets`، `/cart`، `/bookstore`، `/cafe`، `/souvenirs`، `/membership`، `/events`، `/support`، `/admin/login`
  - بررسی اینکه صفحهٔ POS در حالت «بدون دستگاه» بدون کرش رندر می‌شود
  - گزارش جدولی نتایج و exit code غیرصفر در صورت شکست
- اسکریپت `npm run smoke -- https://<app>.liara.run`.

## ۵. مستندات دیباگ لیارا در README
- بخش «عیب‌یابی استقرار روی لیارا»: مشاهدهٔ لاگ‌ها (`liara logs -f`)، خواندن لاگ استارت، تشخیص خطای پورت/`0.0.0.0`، بررسی متغیرهای محیطی، استفاده از `/api/health` و `npm run smoke`، و جدول خطاهای رایج با راه‌حل.

## ۶. حذف لوگوی لاولیبل و ساخت هویت بصری اختصاصی
- ساخت آیکون اختصاصی موزه (نشان طلایی کشتی روی زمینهٔ سرمه‌ای) و جایگزینی `favicon.ico`، `icon-192.png`، `icon-512.png`، `apple-touch-icon.png` و آیکون maskable.
- به‌روزرسانی `manifest.webmanifest` و متاتگ‌های `__root.tsx` تا هیچ اثری از آیکون پیش‌فرض نماند.
- افزودن تصویر og اختصاصی برای اشتراک‌گذاری.

## ۷. نسخهٔ ویندوزی و اندرویدی
- **ویندوز**: بستهٔ کیوسک شامل `scripts/launch-kiosk.bat` (موجود)، یک اسکریپت نصب که میان‌بر دسکتاپ و اجرای خودکار در startup می‌سازد، و راهنمای اجرای هم‌زمان `pos-bridge`.
- **اندروید**: بستهٔ PWA/TWA — `assetlinks.json`، پیکربندی Bubblewrap برای ساخت APK/AAB از همین دامنه، و راهنمای گام‌به‌گام ساخت خروجی در `docs/ANDROID.md` (کارت‌خوان روی اندروید فقط در صورت وجود pos-bridge در همان شبکه کار می‌کند؛ این محدودیت مستند می‌شود).
